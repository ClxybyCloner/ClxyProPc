## مسیریابی پیشرفته VPN (Advanced VPN Routing)

ترافیک CLXY از یک مسیر چندلایه عبور می‌کند — نه یک تک‌جهش VPN:

در این معماری، از ترکیب فناوری Xray و زیرساخت Mozilla VPN برای ایجاد یک مسیر ارتباطی چندلایه استفاده میشود. هدف، افزایش انعطافپذیری در مدیریت ترافیک، جداسازی مسیرهای ارتباطی و کنترل دقیقتر ترافیک ورودی و خروجی است.

ویژگیها:

* مسیریابی چندلایه: ایجاد زنجیره ارتباطی میان لایه ورودی و خروجی VPN.
* یکپارچهسازی Mozilla VPN: استفاده از زیرساخت WireGuard برای مدیریت مسیر خروجی.
* مسیریابی هوشمند: امکان هدایت ترافیک بر اساس سیاستهای تعریفشده.
* مدیریت تونل اختصاصی: کنترل مستقل مسیر ارتباطی و وضعیت تونل خروجی.
* محافظت از IP: جلوگیری از افشای آدرس IP اصلی در شرایط قطع تونل.
* مدیریت خطا و بازیابی: پیشبینی سازوکارهای کنترل اتصال و بازیابی مسیر ارتباطی.

ساختار ارتباطی:

VLESS → Xray Core → Linux Routing → Mozilla VPN → Internet

این ساختار با هدف ایجاد یک زیرساخت ارتباطی منعطف، قابل توسعه و قابل مدیریت طراحی شده است.

## 🖥️ نسخه ویندوز — هایپر و کوانتوم

- **دو موتور در یک برنامه** — **هایپر CLXY**: لایه خروجی Mozilla VPN در مسیر مسیریابی چندلایه CLXY، روی HTTP/3 MASQUE با انتخاب خودکار خروجی و لیست سرور زنده با پینگ واقعی. **کوانتوم CLXY**: مش مستقیم anycast با قفل سریال، لیست سرور با ۱۶ رله و پینگ واقعی TCP، و امکان پین کردن رله.
- **کاملاً پرتابل** — بدون نصب. هر جا اکسترکت کنی اجرا می‌شود (دسکتاپ، فلش). همه‌ی تنظیمات و اطلاعات کنار فایل اجرایی در پوشه‌ی `user-data` است — چیزی در رجیستری و `%APPDATA%` نمی‌نویسد.
- **دو حالت** — **حالت VPN**: مسیریابی کل سیستم با آداپتور Wintun TUN. **حالت پروکسی**: پروکسی محلی SOCKS5 (`127.0.0.1:1080`) و HTTP (`127.0.0.1:8080`) با امکان اشتراک‌گذاری در شبکه‌ی محلی (`:1081`). حالت پروکسی نیازی به دسترسی ادمین ندارد.
- **به‌روزرسانی درون‌برنامه‌ای که جا نمی‌زند** — دانلود در پس‌زمینه انجام می‌شود و اگر پنجره را ببندی، بعد از باز کردن ادامه پیدا می‌کند؛ وقتی دانلود آماده شد، نصب و ری‌استارت.
- **یکپارچگی با دسکتاپ** — آیکون سینی با وضعیت زنده‌ی اتصال، اتصال و قطع از سینی، اعلان‌های ویندوز و اسپلیت تانلینگ (لیست برنامه‌های مستثنا).

## 🧠 معماری هسته‌ی CLXY

CLXY رابط کاربری Flutter را با یک هسته‌ی شبکه‌ی Go ترکیب می‌کند. هسته به‌صورت یک دیمون کناری در کنار اپ اجرا می‌شود — سمت کاربر در مسیر مسیریابی چندلایه CLXY. رابط کاربری از یک پل محلی و API لوپ‌بک برای مدیریت تنظیمات و خواندن وضعیت اتصال استفاده می‌کند، در حالی که هسته ترافیک شبکه را مدیریت می‌کند.

در حالت VPN، یک آداپتور Wintun یک اینترفیس مجازی TUN می‌سازد. یک پشته‌ی TCP/IP در فضای کاربر بسته‌ها را پردازش می‌کند و اتصال‌های TCP را به پروکسی SOCKS5 هسته می‌فرستد. ریزالور داخلی DNS نام دامنه‌ها را به آدرس‌های IP موقت نگاشت می‌کند تا قوانین مسیریابی همچنان بتوانند دامنه‌ها را تشخیص دهند. این قوانین انتخاب می‌کنند که از پروکسی استفاده شود، اتصال مستقیم برقرار شود یا اتصال مسدود شود. انتخاب اپ‌ها هم مشخص می‌کند کدام برنامه‌ها از VPN استفاده کنند.

هسته با HTTP/2 CONNECT روی TLS یا HTTP/3 CONNECT روی QUIC به گیت‌وی وصل می‌شود. از آن‌جا ترافیک مسیر چندلایه CLXY را طی می‌کند: VLESS → Xray Core → Linux Routing → Mozilla VPN → Internet. حالت «فقط پروکسی» از همان هسته استفاده می‌کند بدون این‌که VPN سراسری روی دستگاه بسازد. مسیر VPN ویندوز TCP و DNS را پوشش می‌دهد؛ بقیه‌ی ترافیک UDP تونل نمی‌شود.
